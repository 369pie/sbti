## 零、战略全局判断：为什么现在必须做 UGC 平台

### 0.1 WTFTI 的内容瓶颈

| 问题 | 数据/观察 | 影响 |
|------|-----------|------|
| 所有宇宙由团队独立生产 | 15 个宇宙 × 29 型 = 435 套四段式文案 + 435 张人物图 | 内容生产完全依赖核心团队，瓶颈明显 |
| 新宇宙上线周期长 | 每个宇宙从概念到上线 ~2-4 天（高质量）到 1-2 周 | 无法满足小红书热点时效性（48h 窗口期） |
| 缺乏用户视角的内容创新 | 团队视角 vs 博主/用户视角，后者更懂小红书传播语感 | 内容同质化风险上升 |
| IP 热点错失 | 甄嬛传/苍兰诀/繁花等热剧 → 需要即时出"XX-TI" | 靠团队响应太慢 |

### 0.2 UGC 平台的战略角色

```
WTFTI 生态金字塔：

     ┌──────────────┐
     │  付费深度产品   │  ← SoulTI 灵魂信、CPTI 深度合盘（团队精品）
     │  (PGC 精品)    │
     ├──────────────┤
     │  官方宇宙矩阵   │  ← 经典、鸟格、修仙、灵鉴等（团队标准品）
     │  (PGC 标准品)   │
     ├──────────────┤
     │  UGC 创作者宇宙 │  ← 博主自建题库+人格+图鉴（创作者生产）  ★ 本文焦点
     │  (UGC 规模化)   │
     ├──────────────┤
     │  测评引擎底盘   │  ← 15 维度评分、29 型匹配、Canvas 分享图（平台基础设施）
     │  (平台能力层)    │
     └──────────────┘
```

**UGC 不是"锦上添花"——是 WTFTI 从"测试工具"变成"测试平台"的关键转折。**

| 维度 | 无 UGC | 有 UGC |
|------|--------|--------|
| 内容供给 | 团队瓶颈（月产 2-3 个宇宙） | 创作者并发生产（月产 20-50+） |
| 热点响应 | 48h 内无法上线 | 博主 4h 可出主题宇宙 |
| 流量来源 | 靠平台自运营 | 每个博主自带流量池（粉丝即用户） |
| 收入模式 | 纯 C 端付费 | C 端付费 + 创作者分成 + B 端企业定制 |
| 竞争壁垒 | 内容量 | 内容量 + 创作者生态网络效应 |

## 一、Phase 1: 定位与市场语境

### 1.1 Geoffrey Moore 定位声明

```
给那些 在小红书上做人格/塔罗/测试类内容、拥有 1000-100000 粉、
       靠互动测试涨粉但苦于"没有自己的测试产品"的内容创作者，

WTFTI 创作者平台 是一个 「人格测试创作引擎」，

它让博主 不需要会写代码、不需要找设计师、不需要搭服务器，
只需要提供 主题创意 + 题目文案 + 人格定义 + 图鉴素材，
就能在 4 小时内上线一套完整的、有专业评分系统、
有精美分享卡片、有结果页面的人格测试产品。

不同于 Typeform/Quiz-Maker（纯问卷工具，无人格系统，无社交传播机制），
       金数据/腾讯问卷（企业表单工具，不懂 Z 世代语感），
       和自建小程序（需要开发者、设计师、服务器，成本 5000+ 元起步），

WTFTI 创作者平台 提供的是
「心理学级评分引擎 + 小红书级传播模板 + 即用即上线的零代码创作工具」
——博主只管出创意，我们负责把创意变成专业产品。
```

### 1.2 差异化象限

```
                    创作自由度 ↑
                         |
    WTFTI 创作者平台      |      自建小程序
   ┌──────────────┐      |     ┌──────────┐
   │零代码+专业引擎 │      |     │完全自定义  │
   │传播机制内置    │      |     │开发周期长  │
   │社交分享优化    │      |     │无社交机制  │
   └──────────────┘      |     └──────────┘
                         |
  ─── 低成本/快 ──────────┼─────── 高成本/慢 ───
                         |
   ┌──────────────┐      |     ┌──────────┐
   │模板化/泛化    │      |     │专业工具   │
   │无人格系统     │      |     │非消费者向 │
   │无传播优化     │      |     │学习成本高 │
   └──────────────┘      |     └──────────┘
    Quiz-Maker/趣测       |    Typeform/SurveyMonkey
                         |
                    模板受限 ↓

WTFTI 占据的是: 「高创作自由度 × 低成本/快速」的蓝海象限
```

### 1.3 Proto-Personas（创作者用户画像）

#### Persona C1: "测试类内容博主" — 阿星（占目标创作者 45%）

| 维度 | 描述 |
|------|------|
| **画像** | 24 岁，成都，小红书 3000-30000 粉，主做 MBTI/塔罗/心理测试类内容 |
| **核心痛点** | 每次做"选牌"帖、"测你是什么XX"帖，互动量极高但流量无法沉淀——用户玩完就走，粉丝增长靠单条爆款 |
| **现有工具** | 用 Canva 做图 + 手动在评论区告诉用户"选 A 的你是…"，极其低效 |
| **核心需求** | "给我一个专业的测试工具，让用户扫码就能做，我只需要出题和写结果" |
| **付费意愿** | 免费版足够引流；如果付费版能帮她直接在测试里放个人品牌+粉丝导流，愿意付 ¥29-99/月 |
| **裂变价值** | ⭐⭐⭐⭐⭐ 她的每条帖子就是 WTFTI 的免费广告，每个"扫码测试"都是平台新增 |
| **WTFTI 给她的** | 不用自己搭测试系统，专注创意和内容 → 扫码引流 → 数据看板看效果 |

#### Persona C2: "IP 热点追踪博主" — 小橙（占目标创作者 25%）

| 维度 | 描述 |

| **核心需求** | "热剧一出，我 4 小时内就能出一个'你是XX里的谁'测试，扫码就能玩" |

| **裂变价值** | ⭐⭐⭐⭐⭐ 热点窗口期短（48h），谁先出谁吃肉，她需要最快的工具 |

### 1.4 JTBD 深度分析

#### 功能性任务（Functional Jobs）

| Job | 重要度 | 当前满足度 | 差距分析 |
|-----|--------|-----------|----------|
| 创建自定义题库（非固定 62 题） | ⭐⭐⭐⭐⭐ | 🔴 0% | 当前所有宇宙共用同一套 62 题，创作者无法自定义 |
| 定义自己的人格类型体系 | ⭐⭐⭐⭐⭐ | 🟡 30% | UGC Phase 0 允许 re-skin 29 型，但不允许创建新类型 |
| 上传自定义图鉴/人格插图 | ⭐⭐⭐⭐⭐ | 🔴 0% | 当前所有图鉴由平台生成（RunningHub） |
| 配置评分/判定规则 | ⭐⭐⭐⭐ | 🔴 0% | 固定 15 维度 Euclidean 匹配，创作者无法自定义 |
| 快速上线（<4h 从创意到可用） | ⭐⭐⭐⭐⭐ | 🔴 0% | 当前上线新宇宙需要写代码、部署 |
| 数据看板（UV、完成率、分享率） | ⭐⭐⭐⭐ | 🔴 0% | 无数据分析能力 |
| 分享图自动生成（带品牌信息） | ⭐⭐⭐⭐⭐ | 🟡 50% | Canvas 引擎存在但不支持自定义品牌元素 |
| 付费测试上架和收益分成 | ⭐⭐⭐ | 🔴 0% | 创作者中心页面已有框架设计但无后端实现 |

#### 社交性任务（Social Jobs）

| Job | 说明 |
|-----|------|
| "我有自己的专属测试产品" | 从"转发别人的测试"到"我做的测试被几万人玩" —— 身份升级 |
| "我的粉丝因为测试而记住我" | 测试结果页带博主署名和主页链接 → 品牌心智沉淀 |
| "我比其他博主先出热点测试" | 速度即竞争力 → 工具越快，博主越有优势 |
| "我能看到有多少人玩了我的测试" | 数据看板 = 成就感 + 内容优化依据 |

#### 情绪性任务（Emotional Jobs）

| Job | 重要度 | 说明 |
|-----|--------|------|
| "创作者的自豪感" | ⭐⭐⭐⭐⭐ | "几万人在玩我设计的测试" |
| "专业感加持" | ⭐⭐⭐⭐ | "我的测试不是随便编的，有专业评分引擎" |
| "不焦虑的创作体验" | ⭐⭐⭐⭐⭐ | "不用担心服务器、不用担心bug、不用求程序员" |
| "被平台重视的归属感" | ⭐⭐⭐ | 创作者中心、排行榜、官方推荐 |

#### 痛点（Pains）

1. **"工具荒"**：小红书测试类博主目前没有任何好用的人格测试创建工具，只能做图文互动帖
2. **"热点窗口太短"**：热剧/综艺的内容窗口只有 48h，现有工具/流程无法在窗口期内出产品
3. **"数据黑箱"**：发了测试帖不知道多少人真正完成了测试、分享了结果
4. **"品牌无沉淀"**：用户做完测试只记住了结果人格，不记得是谁做的测试
5. **"变现无门"**：免费测试做了流量但无法直接转化收益

#### 收益（Gains）

1. **"内容工厂化"**：从"每条帖子手工打造"变成"出创意 → 4h 上线 → 发帖 → 数据优化"的标准流程
2. **"流量到资产"**：测试用户数据沉淀为创作者的用户池 → 长期价值
3. **"被动收入"**：付费测试一次上架、持续收益 → 睡后收入
4. **"专业人设"**：拥有自己的人格测试产品 = 在同类博主中脱颖而出

## 二、Phase 2: 问题框架与验证（MITRE Problem Canvas）

### 2.1 向内看（Look Inward）

**核心假设清单：**

| # | 假设 | 验证状态 | 风险等级 | 如果错了 |
|---|------|----------|----------|----------|
| H1 | 小红书测试类博主愿意使用外部工具创建测试 | 🔴 未验证 | 高 | 博主可能觉得"评论区互动就够了" |
| H2 | 创作者能自己设计有效的题库和人格体系 | 🟡 半验证（甄嬛宇宙证明可行，但那是团队做的） | 高 | 创作者可能只会写文案不会设计评分规则 |
| H3 | 简化的评分系统（非 15 维度）对创作者足够 | 🔴 未验证 | 中 | 简化版可能结果不够"准" |
| H4 | 创作者愿意为高级功能付费 | 🔴 未验证 | 中 | 免费增长可能才是核心价值 |
| H5 | 每个创作者宇宙都能自带流量 | 🟡 假设合理（博主发帖 = 引流） | 低 | 部分小博主流量极低 |
| H6 | UGC 内容质量可控 | 🔴 未验证 | 高 | 劣质内容可能伤害平台品牌 |
| H7 | 创作者能自行上传/设计图鉴 | 🟡 合理但需工具支持 | 中 | 可能需要平台提供 AI 图鉴生成 |

**为什么到现在还没做 UGC 开放？**

1. **技术债**：当前宇宙都是硬编码的 TypeScript 文件，无动态加载能力
2. **评分耦合**：所有宇宙共用 15 维度 × 29 型 × 62 题的固定底盘，创作者无法自定义
3. **前端优先**：过去 12 周聚焦前端体验，后端/数据库/API 均未落地
4. **质量标准不明**：没有内容审核流程和质量门槛

**我们的偏见：**

- **"完美引擎"偏见**：总想先把 15 维度引擎做完美再开放 → 实际上创作者可能只需要 3-6 个维度
- **"先 PGC 后 UGC"偏见**：总觉得要先做够官方宇宙再开放 → 实际上 UGC 才是规模化的答案
- **"创作者会用专业工具"偏见**：以为创作者能理解"维度""评分权重" → 实际上需要极度简化

### 2.2 向外看（Look Outward）

**类比市场研究：**

| 平台 | 模式 | 创作者赋能 | 商业化 | 对 WTFTI 的启发 |
|------|------|-----------|--------|-----------------|
| **Typeform** | 通用表单/问卷 SaaS | 高自由度但无人格系统 | B 端订阅 $25-83/月 | 交互设计参考；但太"通用"不够"玩" |
| **Quiz-Maker** | 测试/问卷工具 | 支持 Personality 类型但非常基础 | Freemium + $13-79/月 | 人格类型分配逻辑参考 |
| **Interact** | 营销测试工具 | AI 生成测试 + 结果分流 | $39-209/月 | Lead capture 机制参考 |
| **BuzzFeed Quizzes** | 媒体型 UGC 测试 | 编辑团队+社区投稿 | 广告变现 | 病毒传播模型参考 |
| **小红书搜索题/评论区测试** | 草根 UGC | 零工具支撑 | 无商业化 | **这就是我们要替代的"低效原始态"** |
| **趣测 / 爱测试** | 国内测试小程序 | 可创建简单测试 | 广告 + 付费 | 国内验证但体验/品质差 |

**关键发现：**

> **没有任何一个工具同时具备：人格心理学级评分引擎 + 小红书级社交传播优化 + 零代码创作工具 + 创作者收益分成。**
> 
> 这是 WTFTI 的独占位机会。

**谁经历这个问题？**
- 小红书上 10 万+ 做 MBTI/塔罗/测试类内容的博主
- 每天在评论区手动做"你选 A 你是 XXX"的创作者
- 想给粉丝做"品牌专属测试"但找不到工具的 KOL

**谁从现状获益？**
- 现有测试工具平台（趣测等）——但它们太粗糙
- 外包开发者——博主花 5000+ 找人做小程序

### 2.3 重新框架（Reframe）

**原始问题**：如何让创作者在 WTFTI 平台上创建自己的题库、人格类型、图鉴和判定规则？

**重构的核心问题：**

> 小红书上存在大量以"人格/类型/配对"为核心的内容创作需求，但创作者缺乏将创意快速转化为可交互、可传播、可追踪的人格测试产品的工具。  
> 当前的解决方案要么太专业（自建小程序）、要么太粗糙（评论区手动对答案）、要么太通用（Typeform/问卷工具）。  
> WTFTI 已经拥有成熟的评分引擎、分享机制和多宇宙框架，但这些能力被锁死在"团队硬编码"的交付模式中，无法被创作者使用。

**How Might We：**

> **HMW** 在保持专业评分质量和品牌视觉标准的前提下，让一个不懂代码的小红书博主在 4 小时内从创意到上线一套完整的人格测试？
>
> **as we aim to** 在 90 天内吸引 50+ 创作者入驻、上线 100+ 创作者宇宙、带来 10 万+ 新增测试用户（全部通过创作者自带流量）

## 三、Phase 3: 解决方案探索（Teresa Torres OST）

### 3.1 北极星指标

**平台级**：月活跃创作者数（Monthly Active Creators）× 创作者宇宙产生的月新增用户数

| 指标 | 当前 | 90 天目标 | 180 天目标 |
|------|------|-----------|------------|
| 入驻创作者数 | 0 | 50 | 200 |
| 上线创作者宇宙数 | 1（甄嬛，官方示范） | 100 | 500 |

 小红书测试类活跃博主 ~10 万

 → TAM ≈ ¥0.5-2 亿/年

综合 TAM ≈ ¥4-5 亿/年

WTFTI 可服务的细分市场：

### 6.1 Creator Studio 核心功能拆解

#### 6.1.1 题库编辑器

```
创作者创建题库的核心流程：

1. 选择评分模式
   ├── 模式 A: 维度打分型（推荐）
   │   → 定义 3-8 个维度轴
   │   → 每道题的每个选项给不同维度加分
   │   → 最终用维度组合匹配人格类型
   │
   ├── 模式 B: 直接匹配型（简单）
   │   → 每个选项直接指向一个人格类型
   │   → 最终统计哪个类型得票最多
   │
   └── 模式 C: 混合型（高级）
       → 部分题用维度打分，部分题用直接匹配
       → 支持条件分支（答了 A 跳到第 5 题）

2. 创建题目
   ├── 题干文本（≤100 字）
   ├── 选项（2-6 个）
   │   ├── 选项文本
   │   ├── 选项图片（可选）
   │   └── 评分权重（按模式配置）
   ├── 题目分类标签（可选）
   └── 随机出题设置（是否从题库随机抽取）

3. 预览 & 测试
   → 创作者可自己完成测试，验证结果分布
```

#### 6.1.2 人格类型定义器

```
创作者定义人格类型的流程：

1. 基础信息
   ├── 人格名称（如"控场王"）
   ├── 4 字母代号（如"BOSS"）
   ├── 代表 emoji
   ├── 一句话标语
   ├── 主题色（hex 色值，可从色板选择）
   └── 金句引用

2. 人格图鉴图片
   ├── 上传自有图片（JPG/PNG，≤5MB）
   ├── 或 AI 生成（输入描述 → RunningHub 出图）
   └── 裁切预览（适配分享卡片尺寸）

3. 四段式文案
   ├── 命中语（hit）—— 一句话精准打击
   ├── OS 解读（os）—— 2-5 段人格描述
   ├── 症状清单（symptoms）—— 3-6 条行为特征
   └── 收尾语（closer）—— 温暖/自嘲/反转结尾

4. 评分映射（维度打分模式）
   └── 定义该人格在每个维度上的高/中/低位置
       例如：控场王 = { 外向: 高, 理性: 高, 主导: 高 }
```

#### 6.1.3 评分规则配置器（简化版）

**核心设计原则：让不懂心理学的博主也能设计出"感觉准"的测试。**

```
简化评分系统 vs 当前系统对比：

当前系统（PGC）：
  15 个维度 × 3 级（H/M/L）× 62 题 × 29 型
  → 创作者无法理解也无法配置

简化系统（UGC Level 2）：
  3-8 个维度 × 2 级（H/L）× 10-30 题 × 4-16 型
  → 创作者可理解可配置

简化系统（UGC Level 1）：
  0 维度 × 直接匹配 × 5-15 题 × 4-12 型
  → 最简单：每个选项直接对应一个类型，计票定结果
```

**维度打分模式配置 UI：**

```
Step 1: 定义你的评分轴（3-8 个）

  轴 1: [  外向 ←————→ 内向  ]
  轴 2: [  理性 ←————→ 感性  ]
  轴 3: [  主导 ←————→ 顺从  ]
  轴 4: [  冒险 ←————→ 稳重  ]
         [+ 添加更多轴]

Step 2: 为每道题的选项配置分值

  Q1: "周末你更想做什么？"
  ├── A. 约朋友出去嗨   → 外向 +2, 冒险 +1
  ├── B. 一个人看书     → 内向 +2, 稳重 +1
  ├── C. 去新餐厅探店   → 外向 +1, 冒险 +2
  └── D. 在家追剧       → 内向 +1, 稳重 +2

Step 3: 为每个人格定义维度档位

  "社牛本牛" = 外向:H + 冒险:H + 主导:H
  "社恐达人" = 内向:H + 稳重:H + 顺从:H
  ...

→ 系统自动用距离匹配算法得出结果
```

### 附录 C: 从当前 UGC Phase 0 到 Phase 0.5 的技术迁移

```
当前状态（Phase 0）：
  src/lib/ugc/types.ts       → TypeScript 接口定义 ✅ 可复用
  src/lib/ugc/registry.ts    → 静态导入注册 → 需改为 Supabase 查询
  src/lib/ugc/universes/*.ts → 硬编码宇宙配置 → 迁移到数据库
  src/app/ugc/[universe]/    → 静态路由 → 改为动态 /c/[universe]/

迁移计划：
  1. 保留 types.ts 接口定义作为 TypeScript 类型约束
  2. registry.ts 改为 Supabase 查询（getUgcUniverse → supabase.from('universes')）
  3. 甄嬛宇宙数据从 .ts 文件导入 Supabase 作为种子数据
  4. 新增 /c/ 路由前缀区分 UGC 宇宙（不影响现有 /ugc/ 路由）
  5. 评分引擎新增 flexible-scoring.ts，不改动现有 scoring.ts
```
