# CPTI 2.0 升级战略

> 一句话定位变化：
>
> v1.x：「3 分钟测出你和 ta 是什么关系」 — 工具
>
> **v2.0**：「16×25 关系图鉴 · 你和重要的人之间，第一次有了被命名的资产」 — 女性长期持有的关系档案

---

## 0. Why now（升级背景）

CPTI 在 viral sprint 2（2026-04-19）后已经具备完整的 16 人格 × 25 关系类型 × 5 场景 SEO 着陆 × 收集图鉴 × 周榜，但仍是一次性测试工具。

同期 XPTI 已经走完 v2.0 → v3.0 的 "asset-ization"（couple 报告 / archive / ITC 理论 / 4 档 SKU）路径，验证了"从测一次到长期持有"的产品形态在本站可行。

CPTI 此刻面临 3 个真实问题：

1. **结构性同质化**：用户认知中"测我和 ta 的关系" ≈ "测我对亲密关系的偏好"，CPTI 与 XPTI 边界模糊，导致 CPTI 被误读为 XPTI 的"轻量替代"。
2. **变现单点**：仅 1 个 `cpti-deep-relationship` SKU，没有 archive / couple / pass，LTV 远低于 XPTI 的 4 档阶梯。
3. **男性参与黑盒**：女性发出配对邀请后，男性常常被动答完即走，没有"他的视角"独立成立的产品价值，无法形成女性希望的"关系一起持有"。

这次升级不是再加 dim、不是改 UI 皮肤，而是 **把 CPTI 重新定义为关系本身的命名权**：你和你妈、你和闺蜜、你和那个暧昧 3 个月的人、你和死对头同事 —— 每一段都值得有一张正式的"关系身份证"，并被女性当作长期资产持有。

## 1. CPTI vs XPTI：边界澄清（产品立场）

| 维度 | **XPTI** | **CPTI** |
|---|---|---|
| **核心问句** | 我想要什么样的亲密？ | 我和这个具体的人，是什么关系？ |
| **测试单位** | 个人（关于"理想中的他"） | 关系（关于"具体的我们"） |
| **维度结构** | 9 dim · 12 原型（个人偏好图谱） | 5 dim × 5 dim = 25 关系类型 + 16 角色（关系动力学） |
| **场景宽度** | 仅亲密 / 性 / 浪漫关系 | **任何二人关系**：恋人、闺蜜、家人、同事、死对头 |
| **情感任务** | 自我理解（向内）—— 「原来我是这样的人」 | 关系命名（向外）—— 「原来我们是这种 CP」 |
| **社交形态** | Couple Report（亲密关系内部） | Pair Code + Gallery（任意社交关系，公开可炫耀） |
| **复用性** | 一年一测（你变化慢） | **一段关系一次**，可以测 N 段（你和不同人是不同 CP） |
| **品牌色** | 枯玫瑰 / 深酒红（私密、夜） | 玫瑰陶土 / 暖米（社交、可发圈） |
| **典型 use case** | "我想看看自己 XP 是什么。" | "我跟我闺蜜测了，她是 Mama 我是 Wildboy 哈哈哈。" |

**战略推论**：

- XPTI 是**深度向内**的"私人档案"，单人 LTV 来自重测 + couple 升级。
- CPTI 是**广度向外**的"社交图鉴"，单人 LTV 来自**关系数 × 关系类型数**（同一个用户测 5 段关系 = 5 张关系卡）。
- 两者**不是替代品，是互补品**：XPTI 解决"我是谁"；CPTI 解决"我和你是谁"。
- 战术含义：CPTI 应该把**关系数量**作为 north-star metric（人均测过的关系段数），而不是测试完成率。

## 2. Phase 1 — Positioning & JTBD（女性向重写）

### 2.1 Geoffrey Moore Positioning（v2.0）

```
For 18–32 岁、喜欢用人格/星座/MBTI 给自己和身边人贴标签的女性用户

  that need 一种比"你是 ENFP"更精确、比"我们是闺蜜"更生动的方式，
            来命名她和身边每一个重要的人之间到底是什么关系

  CPTI is a 关系角色图鉴（Relationship Role Codex）

  that 用 5 个关系维度 × 16 个角色 × 25 种关系类型，
        给她生命中的每一段二人关系，发一张可命名、可收藏、可发朋友圈的"关系身份证"

Unlike MBTI / 心理测试小程序 / XPTI（个人 XP 测试）

  CPTI provides 「关系本身」作为最小测试单位 —— 同一个你，和不同的人是不同的 CP，
                每一段关系都是一张独立可持有的资产，可以集齐、可以重测、可以共同署名。
```

### 2.2 Proto-personas（女性向 3 类）

| 标签 | **小红 · "贴标签收藏家"** | **婷婷 · "暧昧期侦探"** | **Anna · "高浓度闺蜜组"** |
|---|---|---|---|
| 年龄 | 22 · 大三 | 27 · 互联网产品 | 25 · 4 人闺蜜组群主 |
| 关系状态 | 单身偶有暧昧 | 暧昧 3 个月卡住 | 稳定恋爱 · 重心在女性友谊 |
| 痛点 | "MBTI 我都背完了，太基础。" | "我 quizz 他到底真心吗，星座说不清。" | "我们 4 个谁是 Mama 谁是 Wildboy 我有数。" |
| 核心 JTBD | 给"我和身边人"做一本可发的人物关系档案 | 把"暧昧不安"翻译成可读的关系结构 | 用 CPTI 做闺蜜组的内部黑话和身份系统 |
| 出口动作 | 集齐 25 类关系，做"我的 2026 关系图鉴" | 把测试结果发给那个人："你看我们" | 4 人组群里互相测，发组合海报 |
| 付费意愿触发 | 收集到 12/25 → "把图鉴年卡留下来" | 关键关系深度报告（30 共修建议 / 8 雷区） | 4 人组合年度合照 + 周年纪念 |

**关键发现**：3 类用户的付费动机都不是"想知道更多关于自己"，而是"想把这段关系/这本图鉴**留下来、署上名**"。这跟 XPTI（个人 archive）的动机本质不同。

### 2.3 JTBD（Outcome 语句）

| 类型 | Job Statement |
|---|---|
| **Functional** | When 我和某个人的关系处在我说不清的状态时，I want to 用 3 分钟把它翻译成一个可命名的"关系类型"，so I can 跟自己和别人讲清楚我们到底是什么 |
| **Social** | When 我想在朋友圈/小红书展示我的人际关系世界时，I want to 拿出一张高级感、有专属编号、专属图标的关系卡，so I can 让人看到"我和我重要的人都是有故事的" |
| **Emotional** | When 一段重要关系正在变化时，I want to 有一份外部权威给它做"年报式回顾"，so I can 用结构感缓解关系不确定性带来的焦虑 |

### 2.4 Pains / Gains

**Pains（女性用户实际抱怨）**

- 「我跟我妈每次吵架都说不清是哪儿的事」（家人关系无语言）
- 「我跟他到底是暧昧还是 situationship 我自己都不知道」（关系定义焦虑）
- 「闺蜜变了，但我说不出哪里变了」（关系演化不可见）
- 「MBTI 配对那种太老了，我都看腻了」（既有产品 fatigue）
- 「测完很爽，但下次想找回来找不到」（无 archive，无资产沉淀）

**Gains（v2.0 要满足）**

- 一段关系测完 → 永久保留 → 一年后可重测对比
- 同一个用户 → 可以测 N 段关系 → 看到自己在不同人面前是不同角色
- 关系结果 → 有"专属编号 + 限定鉴定章"（已有，要强化）
- 关系卡 → 可以双方共同署名（双签 / 双向解锁）
- 集齐 → 不只是 toast，而是**实物感的"年度关系图鉴册"**

## 3. Phase 2 — Problem Framing（MITRE Canvas）

### 3.1 Look Inward（我们的假设）

我们一直假设：
- ✅ 用户测试主要驱动力是好奇 → 实际：女性用户更强的是"想给关系一个名字"。
- ❌ 用户来 CPTI 是为了"知道结果" → 实际：结果只是中介，**真正的爽点在"发出去 + 被命名 + 被共鸣"**。
- ❌ 一次测试 = 一次价值闭环 → 实际：女性用户期待"长期持有"和"重测对比"，但我们没给。
- ❌ 男性是"被邀请的 NPC" → 实际：他答完直接走，导致女性发起方拿不到完整对照报告。

### 3.2 Look Outward

| 谁 | 当前体验 | 缺什么 |
|---|---|---|
| 发起测试的女性 | 测完 → 拿到结果 → 邀请 ta → 等 → 拿到对照 | 等的过程没有期待感；ta 不答没有挽回手段 |
| 被邀请的男性 | 收到链接 → 答 12 题（XPTI 模型）/ 20 题（CPTI 当前）→ 看到对照 → 走 | 没有"对他独立成立的"个人价值，只是"帮女朋友答题" |
| 闺蜜组 | 4 人互相测 → 6 对组合 → 没有 group 视图 | 缺少 **N 人组合关系全景图**（pivotal for 闺蜜组场景） |
| 家人关系（妈/姐妹） | 测一次 → 结果偏娱乐 → 不敢发 | 缺少**家人专属版语气**（不能像测闺蜜一样玩梗，要更温柔） |
| 死对头 / 同事 | 测一次 → 结果好笑 → 不敢直接发给本人 | 需要"暗讽友好"的中间态分享卡（可发圈不暴露 ta） |

### 3.3 Reframe — 重新定义问题

**v1.x 我们解决的问题**：「用户想知道自己和某个人是什么关系」

**v2.0 真正要解决的问题**：

> 「成年女性的人际关系世界（恋人、闺蜜、家人、同事）正在被快速重新定义，
> 但她缺乏一个**结构化、可留存、可分享、可演化**的语言系统来命名这些关系。
> CPTI 应该成为这个语言系统本身。」

**HMW 列表**：

- HMW 让一段关系测试结果**值得被女性长期持有**，而不是看完即走？
- HMW 让被邀请的男性，第一次拿到一份**对他个人独立有价值**的报告？
- HMW 让闺蜜组的 6 段两两关系，**形成一个 group 资产**而不是 6 张零散卡？
- HMW 让女性用户**愿意主动发到朋友圈**，且不用担心"暴露被测的那个人"？
- HMW 把"集齐 25 类"的成就感，**升级成可付费的实体感图鉴**？

## 4. Phase 3 — Opportunity Solution Tree

**Desired Outcome（North-Star Metric）**

> **每位活跃女性用户人均测试关系段数 ≥ 3 段**（当前估测 1.4 段）
> 衍生指标：60 天 D60 retention ≥ 22%；付费转化 ≥ 4.5%（v1.x 约 1.8%）

### 4.1 Opportunity 1 — 关系无法被长期持有

> **问题**：测完即走，没有 archive；用户想找回来找不到。

**Solutions**:

- **S1.1 关系档案夹（Relationship Archive）** — 登录后每段测试自动归档；卡片视图，按"对象/闺蜜/家人/同事"分类；支持给关系起昵称、写一句话、添加日期。
- **S1.2 关系年报（Yearly Codex）** — 每年 12 月生成"你的 2026 关系图鉴"长图：所有测过的关系卡 + 总集得多少类 + 跟谁是哪种 CP + 演化时间线。
- **S1.3 重测对比（Re-test Diff）** — 一段关系 90 天后可重测，给出"关系演化对比报告"（哪个维度变了、CP 类型是否迁移）。

**评估**：
- S1.1 可行性 H · 影响 H · 市场契合 H → ⭐ 必做（v2.0 W1-W2）
- S1.2 可行性 M · 影响 H · 市场契合 H → ⭐ v2.1 季节性大杀器
- S1.3 可行性 M · 影响 M · 市场契合 H → v2.1（依赖 S1.1）

### 4.2 Opportunity 2 — 男性是 NPC，闭环在他那里断

> **问题**：被邀请方完成率低；即使完成，也没"自己的价值"，第二天不会回来。

**Solutions**:

- **S2.1 反向报告（His POV）** — 男性答完不仅看到"你们是 X 关系"，还看到"在她眼里你是 [角色名]"+ "如果你想升级关系，先试试这件事"，把他变成被诊断的人。
- **S2.2 男性独立入口** — 把 CPTI 部分场景（"死对头同事"/"死党"）专门做男性向落地页，去掉粉色包装，主打"用结构化方式看清你身边的人"。
- **S2.3 双签关系卡（Co-Signed Card）** — 双方都完成后，关系卡上同时显示两人 ID/昵称 + 双方专属编号，提升"共同持有"的仪式感。

**评估**：
- S2.1 H/H/H → ⭐ 必做（v2.0 W2）
- S2.3 H/H/H → ⭐ 必做（v2.0 W3，付费转化抓手）
- S2.2 M/M/M → v2.1 explore（先靠 S2.1+S2.3 验证）

### 4.3 Opportunity 3 — 单段关系→多段关系→关系网，缺乏聚合产品形态

> **问题**：用户测了 5 段关系，但产品只能呈现成 5 张孤立卡，没有"她的人际关系世界"这个总览。

**Solutions**:

- **S3.1 我的关系星图（My Constellation）** — 个人页用一张 SVG 星图，把测过的所有人作为节点，关系类型作为连线，悬停看关系卡。可以分享。
- **S3.2 闺蜜组 Group Mode** — 3-6 人组队，自动生成所有两两组合的关系卡 + 一张"组合人格画像"（谁是组里的 Mama、谁是 Wildboy、谁是 Vibes）。
- **S3.3 家庭组 Family Mode** — 父母/姐妹专属语气包，结果偏温柔、不带"梗感"，可以转给妈妈。

**评估**：
- S3.2 H/H/H → ⭐ 必做（v2.0 W4，闺蜜组是最大女性社交场） 
- S3.1 M/H/H → ⭐ v2.0 W5（强 FOMO + 强分享）
- S3.3 M/M/H → v2.1（家庭语气模型工程量较大）

### 4.4 Opportunity 4 — 付费只有 1 档，且没有"留下来"的付费理由

> **问题**：当前 `cpti-deep-relationship` 是单段关系深度解锁，付费价值偏"消费内容"，不是"持有资产"。

**Solutions**:

- **S4.1 关系档案年卡（Codex Pass · ¥29/年）** — 解锁 archive 无限存储 + 年报生成 + 重测对比，**对标 XPTI archive yearly**。
- **S4.2 双签限定卡（Co-Sign Premium · ¥9.9/段）** — 双方都付费可拿到"金箔双签限定版"关系卡（专属编号 + 立体卡面 + 可下载 4K 海报）。
- **S4.3 闺蜜组团购（Squad Pack · ¥39/4 人）** — 4 人组团解锁 group 全景报告 + 组合海报 + 一年 archive。
- **S4.4 升级到 Mysti Pass（¥19/月）** — 既有 Mysti 通行证打通 CPTI 全部高级特性。

**评估**：
- S4.1 H/H/H → ⭐ 必做（v2.0 W3，主轴 SKU）
- S4.3 H/H/H → ⭐ 必做（v2.0 W4，配合闺蜜组上线）
- S4.2 H/M/H → ⭐ v2.0 W3（小额冲动 SKU）
- S4.4 已有 → 仅需在 CPTI 内增加锚定文案

### 4.5 Opportunity 5 — 分享形态停留在静态海报，缺少"看了想点"的钩子

> **问题**：CPTI 海报已经做得不错，但小红书/朋友圈刷到时缺乏"我也想测"的拉力，FOMO 钩子弱。

**Solutions**:

- **S5.1 暗讽友好分享卡（Subtle Mode）** — 测同事/死对头/前任时，海报隐藏"被测人"侧的具体角色，只显"你是 Mama / 我们是 [类型]"，点进 H5 才能看完整对照（被测人无社死风险）。
- **S5.2 关系编号系统（Edition Number）** — 已有（每段关系生成"全网第 N 对"），需要前置到分享卡顶部 + 加一句 "*稀有度 Top 3.5%*" 让稀缺感可见。
- **S5.3 测试季节限定皮肤** — 每季度（情人节 / 七夕 / 跨年）出"限定关系卡皮肤"，过期不可解锁，强 FOMO。
- **S5.4 邀请回流引擎（Invite Loopback）** — 被邀请方答完后，自动给邀请方推送"ta 已完成 + 你的对照已生成"的回流通知（站内 + 小程序订阅消息预留接口）。

**评估**：
- S5.2 L 工作量 H 影响 → ⭐ 必做（v2.0 W1，零成本立即上）
- S5.4 M/H/H → ⭐ 必做（v2.0 W2）
- S5.1 M/H/H → ⭐ 必做（v2.0 W3，解决"不敢发"）
- S5.3 M/M/H → v2.0 W6 配合首个节日发布

## 9. 关键风险与不做的事

### 9.1 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| Archive 表上线后未登录用户流失（强制登录墙） | 高 | 中 | 不做硬墙；保留 localStorage 临时态，登录后自动 merge；登录提示放在第 5 个关系测完时 |
| 闺蜜组 Squad Mode 6 人 N²=15 段关系 UI 信息过载 | 中 | 高 | v2.0 限制最多 4 人；6 人挪到 v2.1，配合更强的可视化 |
| 男性反向报告被 KOL 截图反向解读为"PUA 教程" | 低 | 高 | 文案审稿；避免"如何征服她"式语言；用"如何让这段关系更稳"中性表达 |
| 双签限定卡转化率过低（要求双方都付费） | 中 | 中 | 默认 A 付一份，邀请 B 付 ¥9.9 解锁双签；如 B 拒付，A 仍可拿到 A-only 限定版 |
| 节日限定皮肤工程量挤占主线 | 中 | 中 | v2.0 W6 仅做 1 个节日；模板化节日皮肤系统留 v2.1 |

### 9.2 v2.0 明确不做

- ❌ 不做 CPTI 个人 dim 扩容（保持 5D；扩 dim 是 XPTI 的赛道）
- ❌ 不做 CPTI 单独的 LGBTQ+ 内容客制（仅在文案中保持性别中性表述）
- ❌ 不做 dating / matching 形态（与 XPTI v3 战略硬约束一致）
- ❌ 不做付费内容 AI 个性化生成（v2.0 全部 deterministic content pool；AI 留 v2.2）
- ❌ 不重构既有 16 人格 / 25 关系类型 taxonomy（这是 IP 资产，稳定性 > 优化）
- ❌ 不做小程序版（先把 H5 + 小红书着陆做透）
