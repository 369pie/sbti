# UGC 创作者平台执行计划

> Owner: Product + Growth + Creator Platform
> Status: Active
> Priority: P0.5
> Last Updated: 2026-04-17

## 目标

把 UGC 从“功能已可用”推进到“创作者真的能顺手跑起来”。

当前核心矛盾不是后台能力不够，而是：

1. 创作者获批后第一次进入工作台，不知道先做什么。
2. 从创建宇宙到提交审核的路径仍然偏手工，启动成本高。
3. 审核、增长、导流、收益四条链路都有基础版，但激活链路最弱。

## 决策原则

1. 先做激活，不先做复杂商业化。
2. 先做模板和默认路径，不先做高级自由度。
3. 先做可运营的漏斗，再做更多漂亮功能。

## 优先级路线

| 优先级 | 模块 | 为什么先做 | DoD |
|---|---|---|---|
| P0 | 首发激活链路 | 决定 approved creator 能否快速产出第一个宇宙 | 创作者可用模板在 30 分钟内完成第一个可提交草稿 |
| P1 | 创作者导流链路 | 决定博主是否愿意持续推自己的测试 | 结果页和创作者主页都能承接流量 |
| P1 | 内容审核与风控 | 决定 UGC 放量后平台是否失控 | 审核原因结构化、可回退、可复核 |
| P2 | 数据面板升级 | 决定创作者是否知道如何优化内容 | 看到来源、完成率、分享率、题目流失点 |
| P3 | 真支付与真结算 | 决定商业化闭环是否成立 | 在模拟支付验证后再切真实支付 |

## 当前冲刺范围

### Sprint A：激活链路

本轮先交付 3 件事：

1. 模板创建
2. 工作台 onboarding 引导
3. 编辑器 readiness checklist

### Sprint A 用户价值

1. 新创作者不再从空白页开始。
2. 创作者知道“至少需要 2 个维度、5 道题、2 个人格”。
3. 创建后能直接按 checklist 往下走，而不是靠猜。

## Sprint A 交付定义

### A1. 模板创建

- 工作台首页展示 3 套 starter templates
- 点击模板后自动预填宇宙名和 slug
- 创建时自动注入基础维度、题目和人格骨架
- 模板不是最终内容，而是“可编辑骨架”

### A2. 工作台 onboarding

- 首页展示 3 步路线：选模板 → 完成骨架 → 提交审核
- 首页显示当前草稿 / 审核中 / 已发布数量
- 明确告诉创作者第一步该做什么

### A3. 编辑器 readiness checklist

- 设置页：补完宇宙简介
- 维度页：至少 2 个维度（直接匹配模式可跳过）
- 题库页：至少 5 道题
- 人格页：至少 2 个人格
- 给出下一步 CTA，减少迷路

## 下两轮建议

### Sprint B：导流链路

1. 结果页显示创作者署名和主页 CTA
2. 创作者公开主页 / 宇宙合集页
3. 分享卡增加 creator branding 和来源追踪

### Sprint C：审核与质量

1. 审核原因模板化
2. 版权 / IP 风险提示
3. 发布后可回退到草稿
4. 下架和复审流程

## 北极星指标

### 激活指标

1. `approved -> first studio visit` 转化率
2. `first studio visit -> first universe created` 转化率
3. `created -> submitted for review` 转化率
4. 首个宇宙提交审核耗时中位数

### 质量指标

1. 首次提交被驳回率
2. 发布后 7 天内平均测试数
3. 发布后分享率

## 当前结论

UGC 这块最值得先做的，不是继续加后台功能，而是把“第一次开始创作”这一步做顺。只要创作者的启动成功率显著提升，后续导流、审核、收益和真实支付才值得继续加码。
