# WTFTI 无限宇宙套图扩展方案

> 核心思路：以 29 人格 × 15 维度为不变底盘，通过 IP 映射 + 风格换肤，持续批量产出图鉴套图。
> 每套新宇宙 = 一次免费的小红书传播事件。

## 一、品牌视觉资产：已确立的两套独立风格

### 1.1 WTFTI 经典版 — 3D POP MART 潮玩风

| 属性 | 规格 |
|------|------|
| 风格名 | **3D Chibi POP MART Designer Toy** |
| 材质 | 高品质哑光乙烯 (matte vinyl)，POP MART 盲盒质感 |
| 比例 | 2–2.5 头身比，大圆头 + 短胖四肢 |
| 表情 | **极度夸张**，接近 meme 级别（尖叫、崩溃、翻白眼） |
| 道具 | 3–5 个悬浮微缩道具围绕角色 |
| 背景 | 纯白、居中、角色占画面 60–70% |
| 配色 | 每个人格一个强调色，整体高饱和 |
| 文字规则 | **只许出现中文，绝对禁止英文** |
| Prompt 前缀 | `3D render style, chibi POP MART designer toy collectible, high-quality matte vinyl finish, pristine toy texture, 2 to 2.5 head-body ratio...` |

### 1.2 班TI 职场版 — 充气乙烯手办 (Inflatable Vinyl Toy)

| 属性 | 规格 |
|------|------|
| 风格名 | **Inflatable Vinyl Toy（充气乙烯手办）** |
| 材质 | **光泽 PVC 充气塑料**，表面有高光反射 + 充气接缝线 |
| 比例 | 2–2.5 头身比，整体膨胀感，像充满气的气球人偶 |
| 质感关键词 | shiny, smooth, glossy reflections, inflatable, PVC, balloon-like, pumped full of air |
| 绝对不能 | 哑光 / 布料 / 黏土 / 真人皮肤 — 必须一眼就是充气塑料 |
| 道具 | 2–3 个同材质充气小配件悬浮或手持，不超过 3 个 |
| 背景 | 干净纯色 / 简单渐变，摄影棚均匀柔光 |
| 文字规则 | **画面中绝对零文字** |
| IP 映射 | 哈利·波特角色性格 → 职场人格原型 |
| Prompt 前缀 | `An inflatable oversized vinyl toy figure, shiny smooth PVC plastic surface with glossy reflections and subtle seam lines where inflatable sections meet...` |

**两套风格的核心差异：**

| 维度 | WTFTI 经典 (POP MART) | 班TI (Inflatable Vinyl) |
|------|----------------------|------------------------|
| 表面 | 哑光 matte | **光泽 glossy** |
| 体积感 | 实心潮玩 | **充气膨胀** |
| 表情 | 极端 meme 化 | 偏角色演绎 |

## 二、IP 映射宇宙套图：无限扩展模型

### 2.1 核心公式

```
一套宇宙套图 = IP世界观 × 充气乙烯手办风格 × 29人格映射表
```

**不变项（底盘）：**
- 29 种人格 slug（boss, nerd, ctrl, mum, simp ...）
- 15 维度评分系统 & 匹配算法
- 充气乙烯手办的材质/比例/打光规范
- 图鉴卡的排版结构（编号 + 图 + 名称 + 标签）

**可变项（每套新宇宙换的）：**
- IP 角色 → 人格的映射关系
- 角色的服装 / 配色 / 标志性道具
- 每套独立的色彩主题
- 文案可以微调（但核心四段式结构不变）
- 题目可以换一批（场景化到 IP 世界观里）

## 三、UIUX 架构：支撑无限宇宙的产品设计

### 3.1 当前架构问题诊断

| 问题 | 现状 | 影响 |
|------|------|------|
| 硬编码切换按钮 | `TEST_SWITCHES` 数组写死 4 个入口 | 每加一个宇宙就要改 N 个组件 |
| 入口分散 | 首页 hero 区平铺按钮 | 超过 5 个就会拥挤 |
| 没有统一宇宙注册中心 | 每个模块独立目录 + 独立数据 | 无法动态渲染宇宙列表 |
| 结果页无宇宙切换 | 看完班TI 结果想看经典版，需要手动导航 | 用户断流、减少跨宇宙探索 |
| 图鉴馆只有标准版/修仙版切换 | `isXiuxian` boolean | 无法扩展到 N 个皮肤 |

#### 3.2.2 路由层：两种扩展策略对比

**策略 A：继续用独立目录（当前方式，推荐短期）**

```
/wtfti/test/                    ← 经典版
/wtfti/work/test/               ← 班TI·哈利波特
/wtfti/delta/test/              ← 三角洲行动
/wtfti/kings/test/              ← 王者荣耀
/wtfti/avengers/test/           ← 复仇者联盟
/wtfti/[universeSlug]/result/[type]/  ← 动态结果页（可选）
```

优点：SEO 友好、每个宇宙可独立定制、渐进式迁移
缺点：每加一个宇宙要建目录

**策略 B：统一动态路由（推荐中长期）**

```
/universe/[id]/             ← 宇宙落地页
/universe/[id]/test/        ← 测试页
/universe/[id]/result/[type]/ ← 结果页
/universe/                  ← 宇宙总览 / 图鉴中心
```

优点：一套代码覆盖所有宇宙，加新宇宙只需加数据
缺点：需要一次性重构，动态路由在 `output: 'export'` 需要 `generateStaticParams`

**推荐路径：先 A 后 B。** 当前用独立目录快速上 3–5 个 IP 宇宙验证市场，等宇宙超过 5 个再统一迁移到动态路由。

## 四、测试题目系统：共用 vs 独立

### 4.1 核心原则

| 维度 | 决策 |
|------|------|
| 人格数量 | 统一 29 种 |
| 维度体系 | 统一 15 维度 |
| 评分算法 | 统一欧几里得距离匹配 |
| 题目数量 | 统一（当前标准版 ~27 题） |
| 题目内容 | **可不同**（各宇宙可以用不同场景的题） |

### 4.2 三种题库模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **A. 共用标准题库** | 直接复用 `/lib/questions.ts` | IP 套图宇宙（三角洲、王者等），用户只是想换个图鉴风格 |
| **B. IP 场景化题库** | 新写一套题，但测同样的维度 | 深度 IP 宇宙（如班TI用职场场景出题，可选） |
| **C. 随机抽题** | 从总题库中随机抽 N 题 | 提升回测新鲜感（"每次题都不一样"） |

**推荐：对于纯图鉴套图扩展，用模式 A（共用题库）。** 用户测过一次就有人格结果，直接解锁所有宇宙的图鉴卡。不要求每个宇宙都重新做测试——那样用户会烦。

**高级玩法（后续）：** 模式 C 随机抽题 → 每次测试结果可能微妙不同 → 用户有理由"再测一次"。

### 4.3 "测一次，解锁所有宇宙"的产品模式

```
用户做一次测试 → 得到人格结果（如 "人形甘特图" / boss）
                    │
                    ├──→ 自动解锁所有已上线宇宙的 boss 图鉴卡
                    │     - 经典版：POP MART 风格 boss
                    │     - 班TI版：麦格教授充气手办 boss
                    │     - 三角洲版：指挥官充气手办 boss
                    │     - 王者版：曹操充气手办 boss
                    │
                    └──→ 用户可以逐个宇宙查看"同一个人格，不同世界观"
                          → 每个宇宙都是一张可分享的图鉴卡
                          → "我在漫威宇宙是谁？" → 分享 → 传播
```

## 五、图片生产流水线标准化

### 5.1 每套新宇宙的图片生产 SOP

```
第1步：填写映射表
  → 29 个人格 × IP 角色的对应关系
  → 每个角色的标志性道具/配色/服装关键词

第2步：编写 Prompt 模板
  → 基础风格（充气乙烯手办固定前缀）
  → + IP 角色参数（服装、道具、配色）
  → + 人格性格参数（表情、姿态）
  → 参考模板：scripts/banti-launch-prompts.mjs

第3步：生成种子图
  → 先出 3–5 张确认风格统一
  → 确认后批量生产 29 张

第4步：质检 + 微调
  → 检查材质一致性（必须是充气 PVC 质感）
  → 检查 IP 辨识度（一眼能认出是哪个角色）
  → 检查人格辨识度（道具/表情要传达性格）

第5步：导出 + 上架
  → 主图：/public/images/types/{universe-slug}/{personality-slug}.png
  → 缩略图：/public/images/types/thumbs/{universe-slug}-{personality-slug}.webp
  → 更新宇宙配置：src/lib/universes.ts
```

### 5.2 Prompt 模板结构（充气乙烯通用版）

```javascript
// scripts/{universe-slug}-prompts.mjs

const INFLATABLE_VINYL_BASE = `An inflatable oversized vinyl toy figure, shiny smooth PVC plastic surface with glossy reflections and subtle seam lines where inflatable sections meet. ## 六、小红书野蛮增长策略
```

### 6.1 为什么 IP 套图是增长飞轮

```
选一个热门 IP → 制作 29 张图鉴卡 → 在小红书发帖
                                         │
    ┌────────────────────────────────────┘
    │
    ├──→ "你是哈利波特里的谁？" → 粉丝自发传播
    ├──→ "你在王者荣耀里是谁？" → 游戏玩家传播
    ├──→ "你在漫威宇宙是谁？"   → 影迷传播
    │
    └──→ 每套 IP 自带一个现成的粉丝群体
         → 他们看到自己喜欢的 IP 被做成人格图鉴
         → 天然想分享、想 @ 朋友
         → 流量 → 做测试 → 分享结果 → 更多流量
```

### 6.2 发帖节奏建议

| 阶段 | 内容 | 频率 |
|------|------|------|
| 预热 | 发 3–5 张精选图鉴做"猜猜你是谁" | 每套 IP 上线前 2–3 天 |
| 首发 | 29 张全套 + 测试链接 | 集中发布 |
| 长尾 | 每天发 2–3 张单图 + 人格解析文案 | 持续 2 周 |
| UGC | 鼓励用户分享自己的结果截图 | 持续 |

### 6.3 尊重 IP 的边界

> **重要提醒：使用有版权的 IP 做图鉴存在法律风险。**

建议的风险缓解方式：
- 图鉴风格高度抽象化（充气手办本身就不是写实的）
- 避免直接使用 IP 角色名，用暗示性描述（如"一位红发的魔法部关系户"而非"Ron Weasley"）
- 文案中不出现 IP 官方名称，用粉丝黑话/暗语代替
- 定位为"同人向/粉丝致敬创作"
- 如果做到一定体量，考虑获取正式授权或转为原创 IP
