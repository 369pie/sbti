| **鸟TI** | ~31 | 15 | 2 | ~31 | 类似标准 |
| **修仙2.0** | 皮肤覆盖标准题 | 15 | 同标准 | 同标准 | 同标准 |

| **花TI** | 20 | 4 | 5 | 20（全部） | 固定 |

**问题**：只有标准版有题池随机抽样。其余宇宙都是固定顺序全出。

### 1.2 反向题分布——默认倾向偏差（Acquiescence Bias）🔴

标准版 62 题中，仅 10 题为 `reversed: true`（16.1%）。心理量表标准是 40-50%。

| 维度 | 总题数 | 反向题 | 占比 | 风险 |
|-----|-------|--------|------|-----|
| S1 | 5 | 1 | 20% | ⚠️ |
| S2 | 4 | 0 | 0% | 🔴 全正向 |
| S3 | 4 | 0 | 0% | 🔴 全正向 |
| E1 | 4 | 1 | 25% | ⚠️ |
| E2 | 4 | 0 | 0% | 🔴 全正向 |
| E3 | 4 | 0 | 0% | 🔴 全正向 |
| A1 | 4 | 0 | 0% | 🔴 全正向 |
| A2 | 4 | 1 | 25% | ⚠️ |
| A3 | 4 | 1 | 25% | ⚠️ |
| Ac1 | 4 | 0 | 0% | 🔴 全正向 |
| Ac2 | 4 | 0 | 0% | 🔴 全正向 |
| Ac3 | 4 | 0 | 0% | 🔴 全正向 |
| So1 | 4 | 0 | 0% | 🔴 全正向 |
| So2 | 4 | 1 | 25% | ⚠️ |
| So3 | 5 | **5** | **100%** | 🔴 全反向 |

**影响**：用户的"同意倾向"（测量学上的 acquiescence bias）会系统性地把 8 个维度的得分推高、把 So3 的得分拉低，人格判定结果偏差。

### 1.3 Q28 缺少自定义选项

`id: 28`（So2）没有定义 `options`，回退到通用默认（不认同/中立/认同）。虽然不崩溃，但和题目语境（"渴望和信任的人关系密切"）不匹配，降低用户体验和测量精度。

### 1.4 计分颗粒度——只有 5 种可能均分 🟠

每维度抽 2 题，每题 1-3 分，均分只有 5 种可能：

| 组合 | 均分 | → 级别 |
|-----|------|--------|
| (1,1) | 1.0 | L |
| (1,2) | 1.5 | L |
| (1,3) 或 (2,2) | 2.0 | M |
| (2,3) | 2.5 | M |
| (3,3) | 3.0 | H |

**关键问题**：(1,3)=2.0=M 和 (2,2)=2.0=M 在语义上完全不同——前者"极端分裂"，后者"稳定中立"——但系统无法区分。

### 1.5 人格坐标空间——部分人格距离过近 🟠

29 种人格在 15 维欧氏空间中的最近对：

| 人格对 | 欧氏距离 | 差异维度数 |
|--------|---------|-----------|
| atm-er ↔ talk-er | **1.41** | 仅 2 维相差 1 级 |
| ctrl ↔ boss | **1.73** | 3 维相差 1 级 |
| thin-k ↔ solo | **1.73** | 3 维相差 1 级 |
| atm-er ↔ simp | 2.00 | 4 维相差 1 级 |
| party ↔ talk-er | 2.00 | 4 维相差 1 级 |

**atm-er 和 talk-er 距离 1.41**，在只有 5 种离散均分的系统里，一道题的随机波动就能把用户从一个人格推到另一个。

## 二、目标架构：题池扩展 + 随机抽样 + 风格分层

### 2.1 核心设计原则

1. **大题池 + 随机抽样**：每宇宙 80-100 题，每次测试抽 30-35 题
2. **每维度至少 6 题**：抽 3 题/维度，均分有 7 种可能（1.0→3.0 步长 0.33），显著提高分辨率
3. **反向题 40%**：每维度 6 题中 2-3 题反向，消除 acquiescence bias
4. **宇宙皮肤系统**：同一底层测量点，不同宇宙完全不同的题目文案
5. **题目元数据**：每题带 `difficulty`（区分度）和 `theme` 标签，供未来自适应出题

### 2.2 数据模型

```typescript
// ── 升级后的 Question 接口 ──
interface Question {
  id: number;
  text: string;
  dimension: string;           // S1, S2, ... So3
  model: ModelType;
  reversed: boolean;
  options?: AnswerOption[];     // 必填，不再回退默认
  // ── 新增字段 ──
  difficulty?: 'easy' | 'medium' | 'hard';  // 用于未来自适应
  tags?: string[];             // ['relationship', 'workplace', 'solo']
  isDrinkTrigger?: boolean;
  isDrinkBranch?: boolean;
}

// ── 宇宙题目皮肤 ──
interface UniverseQuestionSkin {
  baseQuestionId: number;      // 对应标准题库的 id
  text: string;                // 宇宙主题化的题目文案
  options: AnswerOption[];     // 宇宙主题化的选项文案
}
```

### 2.3 每维度题目数量目标

| 配置项 | 当前 | 目标 | 原因 |
|--------|------|------|------|
| 总题数/标准宇宙 | 62 | **90** | 15维 × 6题 = 90 |
| 每维度题数 | 4 | **6** | 抽3题 → 7种均分 |
| 反向题占比/维度 | 0-100% | **33-50%** | 消除 acquiescence bias |
| 每次抽题/维度 | 2 | **3** | 更细颗粒度 |
| 每次测试题数 | ~31 | **~46** | 15×3 + 1(酒) = 46 |
| 用户体验时间 | ~3分钟 | **~5分钟** | 可接受范围 |

**如果觉得 46 题太多**，可以分两档：
- **快速版**：每维度抽 2 题 → 31 题 ≈ 3 分钟（当前体验）
- **深度版**：每维度抽 3 题 → 46 题 ≈ 5 分钟（更准确）

### 2.4 计分阈值优化

当前阈值 `H ≥ 2.34, M ≥ 1.67` 是基于 2 题设计的。3 题时需要重新校准：

```
3 题可能均分：1.0, 1.33, 1.67, 2.0, 2.33, 2.67, 3.0  （7种）

建议新阈值：
  H ≥ 2.5    (≈ 平均选了 "认同" 2.5/3 次)
  M ≥ 1.5    (中间地带)
  L < 1.5    (≈ 平均选了 "不认同" 2.5/3 次)
```

这样三级分布更均匀，也和用户直觉一致。

### 2.5 人格距离优化

对于距离 < 2.0 的人格对，建议在 profile 中增加 1-2 个区分维度的差异：

| 人格对 | 当前距离 | 建议调整 |
|--------|---------|---------|
| atm-er ↔ talk-er | 1.41 | 在 E3 或 A1 上拉开 1 级差 |
| ctrl ↔ boss | 1.73 | 在 E2 或 So3 上拉开 |
| thin-k ↔ solo | 1.73 | 在 A3 或 E1 上拉开 |

目标：所有人格对距离 ≥ 2.0，理想 ≥ 2.5。

## 三、宇宙题目风格体系

### 3.2 同一测量点的多宇宙示例

**维度 S1（自尊自信）· 正向题 · "面对否定时的第一反应"**

| 宇宙 | 题目 |
|------|------|
| 标准版 | 外人的评价对我来说无所吊谓。 |
| 修仙版 | 渡劫失败时，你会怀疑自己的道心吗？ |
| 毒舌版 | 有人当面说你不行，你的反应是？ |

| SoulTI | 当你在镜中看见自己，你能接受那个全部的自己吗？ |

### 3.3 宇宙皮肤方案（代码层面）

**方案 A：皮肤覆盖（推荐）**

保持一套底层标准题库（90 题×15 维度），每个宇宙只写"皮肤"——覆盖 text 和 options。修仙版其实已经用了这个模式（`XIUXIAN_V2_QUESTION_SKINS`）。

优点：
- 底层维度和计分完全一致，跨宇宙结果可比
- 新增宇宙只需写皮肤文件，不用动计分逻辑
- 可以复用 `shuffleQuestions` 抽样器

缺点：
- 某些宇宙的主题可能和标准题的测量点不完美匹配
- 需要为每个宇宙写 90 套文案

**方案 B：独立题库（当前部分宇宙的做法）**

每个宇宙完全独立的题库 + 维度定义 + 人格映射。

优点：
- 完全自由的测量维度设计
- 适合差异很大的宇宙（如 XPTI 的 4 轴系统）

缺点：
- 每个宇宙需要独立的心理测量设计
- 跨宇宙结果不可比
- 开发和维护成本高

**建议组合**：
- 15 维度宇宙（标准、修仙、毒舌、班TI、鸟TI、王者、三角洲）→ **皮肤覆盖**
- 独立轴系宇宙（XPTI、花TI、SoulTI）→ **独立题库**
- 衍生玩法（打工/恋爱/酒后/今日）→ **独立简化维度**

## 四、随机化策略：让每次测试不一样

### 4.1 当前 shuffleQuestions 的问题

```typescript
// 当前：每维度抽 2 题 → 只有 C(4,2)=6 种组合/维度
shuffleQuestions(QUESTIONS, 2)
// 15 维度都独立抽 → 理论 6^15 ≈ 470亿种组合
// 但实际用户感知：题目内容只有 62 个，重复率高
```

### 4.2 升级后的随机化

```typescript
// 升级：每维度 6 题抽 3 题 → C(6,3)=20 种组合/维度
shuffleQuestions(QUESTIONS_V2, 3)
// 15 维度独立 → 20^15 ≈ 3.3×10^19 种组合
// 用户实际能遇到的题目：90 题中每次见到 46 题
// 连续测两次，约 50% 题目不同 → 体验感完全不同
```

### 4.3 进阶：一致性校验题

从抽到的 3 题中标记 1 题为"校验题"（和另一题测同一个东西但反向表述）。如果两题答案矛盾度过高，可以在结果页里加一行：

> "系统注意到你在某些维度上的回答存在较大波动，这可能意味着你目前正处于某种状态的转折期。"

这在心理学上叫 **内部一致性校验（Cronbach's α 的简化版）**，能让用户觉得"这个测试真的在认真分析我"。

## 五、人格判定优化

### 5.1 当前算法的缺陷

当前用**原始分数的欧氏距离**做匹配：

```typescript
const diff = dim.score - targetNum;  // dim.score 是 1.0-3.0 的连续值
dist += diff * diff;                  // targetNum 是 1/2/3 的整数
```

问题：连续分数 vs 整数目标的距离计算不对称。一个 2.4 分的维度到 H(3) 和到 M(2) 的距离分别是 0.36 和 0.16，差距很小。

### 5.2 建议：加权欧氏距离 + 信心因子

```typescript
function matchPersonality(dimensions: DimensionScore[]): PersonalityType {
  for (const p of candidates) {
    let dist = 0;
    for (const d of dimensions) {
      const target = levelToNum(p.profile[d.id]);
      const diff = d.score - target;
      
      // 新增：维度重要性权重
      // 对于该人格的"标志性维度"（极端值），权重更高
      const weight = (p.profile[d.id] === 'H' || p.profile[d.id] === 'L') ? 1.5 : 1.0;
      
      dist += weight * diff * diff;
    }
    // ...
  }
}
```

这样人格的"标志性极端维度"对匹配的影响更大，减少"泛泛中间分→随机命中"的情况。

### 5.3 建议：匹配信心指标

```typescript
interface TestResult {
  personality: PersonalityType;
  dimensions: DimensionScore[];
  drinkTriggered: boolean;
  // ── 新增 ──
  confidence: number;           // 0-100，匹配信心
  runnerUp: PersonalityType;    // 第二匹配
  runnerUpDistance: number;
}

// 信心 = 1 - (bestDist / runnerUpDist)
// 如果信心 < 30%，结果页可以说：
// "你和 XX 只有一线之隔，说明你是一个复合型人格"
```

这能让"判定不太准"变成"有趣的发现"——用户反而会觉得更准。

## 六、扩展新宇宙的标准流程

新增一个 15 维度宇宙的最小工作量：

### Checklist

```
□ 1. 在 universes.ts 注册新宇宙（id, name, emoji, accent, testPath）
□ 2. 创建 src/lib/{universe}/question-skins.ts
     → 为 90 个标准题写皮肤覆盖（text + options）
     → 确保反向题比例 40%（和标准题一致，皮肤不改 reversed）
□ 3. 创建 src/lib/{universe}/personalities.ts（可选）
     → 如果这个宇宙有独特的人格名/描述/封面
     → 否则直接复用标准版人格 + 皮肤名称覆盖
□ 4. 创建 src/app/{universe}/ 路由（page.tsx, test/page.tsx, result/[type]/page.tsx）
□ 5. 运行 generate-type-images.mjs 生成卡面
□ 6. 在首页 UNIVERSE_CARDS 加入描述
□ 7. 更新 sitemap
```

### 投入估算

| 步骤 | 工作量 |
|------|--------|
| 写 90 题皮肤文案 | 1-2 天（取决于主题难度） |
| 人格名称/描述皮肤 | 0.5 天 |
| 路由 + 组件 | 2 小时（复制改配置） |
| 卡面图片生成 | 1-2 小时（AI 生成） |
