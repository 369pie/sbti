## 0 · 一句话结论

W1-W4 走「自研轻量内核 + 编辑部翻译层」**双层架构**，把命理「黑话坐标」与「她能用的语言」彻底解耦。
内核第一阶段只覆盖 **紫微斗数主星 + 八字四柱 + 当日塔罗运势**，其余等 v3。

## 1 · 我们要解决什么

| 维度 | 必须满足 | 不必满足 |
|---|---|---|
| **正确性** | 紫微 14 主星 / 八字 / 大运 / 流年 排盘必须等价于公开传统算法 | 流派之争（先天 vs 中州 vs 三合）选定一家即可 |
| **语言** | 翻译层：每个术语都有 ≥3 句备选编辑部语 | 不要照抄盘面解读 |
| **法规** | 不做姓名/出生证号收集，"娱乐与自我观察"声明前置 | 不出问事咨询 / 不做"准确率"话术 |
| **成本** | 单次排盘 < 50ms 服务端，0 LLM token | 不必实时 |
| **可演进** | v0 内核能被 v1 工具化、v2 LLM 编排不重写 | 不必一开始就支持所有派 |

## 2 · 候选路线对比

| 路线 | 描述 | 上手成本 | 法规风险 | 长期护城河 | 推荐 |
|---|---|---|---|---|---|
| **A. 直接调 Tianfu API / fork** | 用现成开源命理引擎 | E1，1-2 天 | 中（许可证传染 + 玄学 API 政策不稳） | ✗ 没有差异化 | ✗ |
| **B. 调闭源命理 SaaS** | 灵机/测测/八字 API | E1 | 高（数据共享 + 价格战） | ✗ 受制于人 | ✗ |
| **C. 接通用 LLM + Prompt 算命** | GPT/Claude prompt | E2 | 高（"AI 算命师"红线） | ✗ 没有正确性保证 | ✗ |
| **D. 自研轻量内核 + 编辑部翻译** ★ | 内核做坐标计算，翻译层做语言转换 | E5（W1-W4） | 低 | ✓ 内容 + 数据 + 翻译都是我们的 | ★ |
| E. 自研重型 LLM 命理 Agent | 像 Tianfu Agent 走完整 LLM 推理 | E13+ | 中 | ✓ 但 Q4 再考虑 | 推迟 |

**选 D**。原因：内核是公知算法（不存在版权风险），价值在翻译层 + 长期数据回路 + 「她词条」共建。

```
┌──────────────────────────────────────────────────────┐
│ User: 1992-04-12 凌晨 03:14 · 杭州                    │
└──────────────────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────────────┐
│  Layer 1 · 命理内核（pure function · 0 LLM）          │
│  - 紫微排盘 → 12 宫主星 + 化禄/权/科/忌                │
│  - 八字四柱 → 天干地支 + 大运 + 流年                   │
│  - 当日塔罗 → seeded by birthday × today               │
│  → 输出：结构化 JSON 坐标                              │
└──────────────────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────────────┐
│  Layer 2 · 编辑部翻译（content table + 模板）          │
│  - 每个坐标 → ≥3 句"她能用"的语言                      │

│       "适合发出那条迟到的报价单" /                      │

│  → 输出：1 段 italic 引子 + 1 段日常化建议              │
└──────────────────────────────────────────────────────┘
                    ↓
            Mysti 卡片 / 「她的星图档案」¥39
```

## 5 · MingLi-Bench（外部标尺）

W1 末搭起 50 道测试集：
- 25 个真实出生时间（团队 + 志愿者）
- 25 个边界 case（子时跨日 / 闰月 / 时区）

每个版本上线前必须跑：

```text
我们 v_X 输出     vs     公开命理排盘工具       vs     Tianfu Agent（仅参考）
----------------         ----------------              ----------------------
主星     ✓                主星     ✓                  主星     ✓
化禄     ✓                化禄     ✓                  化禄     ✓
大运     —                大运     ✓                  大运     ✓ (v1 才上)
```

通过率目标：v0 ≥ 80% / v1 ≥ 90% / v2 ≥ 95% / v3 ≥ 98%。

## 6 · 风险表

| 风险 | 等级 | 缓解 |
|---|---|---|
| 排盘算法和主流工具有出入 | 中 | MingLi-Bench 兜底 + 选定一家流派写明 |
| "AI 算命师"被监管投诉 | 高 | 始终前置"娱乐与自我观察"声明 + 不做问事 + 不收姓名 |
| 翻译层语料黑话化 | 高 | 编辑部 SOP：每条必须过"她能不能跟室友说"测试 |
| 用户期待"准确率话术" | 中 | 文案明确："这是坐标，不是预言" |
| 内核维护成本 | 低 | 纯函数 + 单元测试 + 不引第三方运行时 |

---

## 7 · 不做什么

- ❌ 不收集姓名 / 身份证 / 实名出生证明
- ❌ 不做"问事咨询"功能（"我能不能和他在一起？"）
- ❌ 不打"AI 算命师"标签
- ❌ 不展示"准确率 95%"话术
- ❌ 不做风水 / 改运 / 法事 周边
- ❌ 不直接 fork 任何 GPL 命理仓库
