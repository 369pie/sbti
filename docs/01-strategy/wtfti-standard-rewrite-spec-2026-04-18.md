## 1. 为什么要重写

`src/lib/questions.ts`（90 题）是站内"标准入口"的 SBTI 题库。它当年起步就是 SBTI 风格的直接自陈句（"我不够好…", "我很清楚自己…"）。两个问题：

1. **法律风险**：审计结果（[sbti-overlap-2026-04-18.md](./_audit/sbti-overlap-2026-04-18.md)）表明，这套句式渗透到了 8+ 个老宇宙的题目里，结构性回声明显。彻底切干净的方法不是"逐题改字"，而是把整套**写作范式**换掉。
2. **品牌护城河**：WTFTI 的卖点是"场景投射 + 情境弹性"（CAPS 框架）。直陈题型与这个理论自相矛盾——继续用就是在替 16Personalities 打工。

## 2. 写作纲领（v2 题型规范）

每一道 v2 题必须满足以下 5 条：

### 2.1 场景化（Scenario-First）
- 题干必须描述一个**可被画面化的小场景**（30-50 字）
- 禁用 "我_____" 开头的直陈句
- ✅ 例："上司在群里点名表扬同组的另一位同事，没提你。下班路上你的内心戏是："
- ❌ 例："我容易因为外人的评价而内耗。"

### 2.2 三选项都合理（No Obvious Best）
- 三个选项必须是**真实可发生的反应**，不能有"明显高分项"
- 自陈题最大的问题是用户能猜到"哪个选项是测试想要的"，导致社会赞许偏差
- ✅ 三选都是合理选择，差异在情境弹性的不同象限
- ❌ 三选里有一个明显是"对"的（比如"健康沟通 / 冷战 / 摔门走人"，第一个永远被选）

### 2.3 反向计分至少 1/3（Anti-Pattern）
- 至少 33% 题目 `reversed: true`，避免用户机械地"全选 C"
- 反向题的高分选项要描述"看似消极但其实健康"的反应（例如"平静接受"在某些维度反而是高分）

### 2.4 避开已被审计标记的开场（Anti-Echo）
根据 [sbti-overlap-2026-04-18.md](./_audit/sbti-overlap-2026-04-18.md)，以下结构属于"高回声"，禁用：

| 禁用句式 | 说明 |
|---------|------|
| "做决定的时候——" | identify/questions.ts:8 已命中 |
| "看到别人做得好，你的第一反应是？" | banti/cpti/love/work 都有变体回声 |
| "X 没联系的朋友突然找你出来吃饭，你：" | flower 命中最高分 0.48 |
| "此题没有题目，请盲选。" | xiuxian v1/v2 命中 |
| "我和人相处主打一个 X" | xiuxian v2 命中 |

### 2.5 维度纯度（Single-Dimension Loading）
- 一题只测一个 SBTI 维度（避免"既测自尊又测情感"的复合题）
- 写完每题做一次"如果这个人在另一个维度极端，会不会答得不一样"自检——如果答案是"会"，就是不纯，重写。

## 5. 审计自动化

每次 v2 PR 必须跑：

```bash
node scripts/extract-sbti-seed.mjs                              # 重抽种子
node scripts/audit-sbti-question-similarity.mjs --threshold 0.20  # 严档阈值
```

CI 钩子（W2 PR-3 同期接入）：
- `pnpm audit:sbti` → `node scripts/audit-sbti-question-similarity.mjs --threshold 0.30 --strict`，任意一题 score ≥ 0.30 即 fail
- 把报告作为 PR 评论自动贴出
